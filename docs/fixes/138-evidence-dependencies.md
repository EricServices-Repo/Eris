# #138 — selected-source dependency snapshots and dispatch invalidation

Persisted code/test receipts now carry a versioned dependency snapshot: canonical workspace root, repository HEAD/ref, selected file paths/digests/byte counts and main-owned document/worktree epochs. Capture and revalidation run in the context worker, capped at 32 files, 1 MiB per file, 8 MiB across a validation batch and 100 ms file processing; Git probes have 500 ms timeouts. Fixed-size reads prevent file-growth races from decoding unbounded data. Unsupported/missing/oversized sources make coverage unproven rather than silently current. A check without observed file scope is unproven. These are selected-source snapshots, not a whole-repository dependency graph or new verification receipts.

Watcher events and renderer document changes update bounded main-owned epochs; unauthorized/foreign-frame/out-of-workspace notifications are ignored. Dirty documents cannot yield current receipts. Workspace changes conservatively invalidate all code/test evidence while ordinary user preferences remain usable. Epoch rollover cannot revive old snapshots. Renderer notifications contain only path/dirty state, not buffer text. Branch identity and selected bytes are independently rechecked in the worker at selection and dispatch, so missing watcher events do not make changed selected disk files current.

Stale recalled source items are removed before compilation and checked again immediately before transport. Known epoch changes after asynchronous validation are checked synchronously. Native sessions reset on newly revoked dependencies. Generated run messages/summaries exposed to revoked evidence are withheld conservatively, retaining cleaned initial instructions and current permitted input. Canonical history is preserved. Matching bytes are still historical source evidence, never proof that tests ran again.

Capture has a one-second optional deadline, dispatch checking 150 ms, and selection shares the existing foreground deadline. Failure is recent-only/unproven context, not an application error. Already sent requests cannot be recalled; concurrent external OS writes cannot be made atomic with a network dispatch, and this does not claim that guarantee.

Validation: `npx vitest run tests/context-evidence.test.ts tests/memory-dispatch.test.ts tests/context-memory-recovery.test.ts tests/document-store.test.ts` covers source rewrite/rename/delete, large-file caps, branch switches, dirty buffers, stale dispatch/compaction, session reset signalling and preservation of user preferences. Real Git runs only in temporary fixture branches. No live-model or Windows hardware acceptance is claimed.
