# #148 — transactional change outbox and bounded source-catalog replay

SQLite triggers append lightweight create/timeline/control/delete events in the canonical writer transaction, including writes through independent connections. They contain IDs/revisions/epochs, never message text. Timeline events deliberately do not guess append-only semantics from a revision gap. Migration seeds old conversations transactionally and is restart-safe; canonical rows stay authoritative.

The workspace worker replays at most 128 events per header request (explicit replay may request up to 500). Catalog invalidations and their versioned cursor commit in one transaction. Deleted sources retain tombstones until a new source incarnation is processed. A crashed derivation leaves durable events pending; a mismatched/out-of-range cursor resets only derived metadata and replays from canonical event history. Header APIs and the inspector expose pending changes and watermark/high-watermark. Controls revisions now participate in warm-snapshot matching, so independent writers cannot silently retain old exclusions.

This is a source invalidation catalog, not an archive full-text index. Its complete flag describes only catalog replay; it never advertises complete search coverage. Events are retained durably for replay; compaction must wait for future consumers' watermarks. SQLite WAL and FTS5 capability probes are available without requiring FTS5. No optional embedding/model load occurs.

Validation: `npx vitest run tests/context-change-log.test.ts tests/context-continuity.test.ts tests/context-sequence.test.ts tests/context-memory-recovery.test.ts` (41 checks): rollback, crash/restart, two writers, bounded/idempotent replay, controls, delete/recreate and invalid cursor repair. Built-worker smoke also exercises replay/change transfer. Packaged Windows WAL/FTS capability qualification remains a platform check, not an inference from Node tests.
