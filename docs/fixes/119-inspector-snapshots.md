# Inspector snapshot ownership (#119)

Main issues opaque ten-minute snapshot handles bound to the main-frame sender, current profile, registered workspace ID, workspace-switch epoch, thread/source incarnation and revision, and controls revision. Mutation/eviction requests require a valid handle. Initial reads carry the renderer’s selected workspace; a delayed A view cannot silently bind to B. Switching away and back invalidates old handles. Controls are additionally checked against the expected source under the SQLite write transaction, so concurrent rewinds or deletion/recreation cannot race the IPC preflight. Successful actions return a replacement handle. The UI remounts the inspector on workspace changes and disables controls when stale inspection fails. Up to 128 handles are retained per IPC registration; no renderer-supplied filesystem path grants access to a different workspace.
