# 0.6.7 release pipeline repair

The unconditional certification job blocked publishing because reference-machine profiles and paired-model reports did not exist. Pre-1.0 development releases now run the mandatory deterministic context gate and both packaged platform smoke tests, publishing an explicit `certified:false` qualification declaration. Version 1.x+, an explicit certification request, or any supplied evidence workflow ID still requires the unchanged strict verifier. No report, profile, live response, or certification result is fabricated.

The CI audit also failed on GHSA-g3hv-75wg-m249 in minimatch <11.0.1. A root override installs the exact patched 11.0.1 engine for every consumer. Its modern CommonJS object export is incompatible with older callable imports in glob/asar, so the reproducible postinstall hook adapts that export and exposes the Matcher String.match protocol expected by glob 7; the protocol delegates directly to the fixed nonrecursive Matcher.test implementation. Matching, parsing, and the upstream security limit remain unchanged. The hook refuses any unexpected engine version and is idempotent. Tests exercise actual legacy glob and asar packaging, including native-file unpacking, and both platform CI builds must pass before integration. There is no audit allowlist or severity suppression. Remove the export shim when packaging dependencies uniformly support the modern API.
