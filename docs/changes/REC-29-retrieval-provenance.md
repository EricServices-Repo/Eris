# REC-29 / #74: calibrated local retrieval and external embedding boundary

Implemented against main d9f7a1d, 2026-10-28. Workspace retrieval continues to use lexical/path/symbol signals and deterministic hash128 vectors. Settings now explicitly say that choosing an external embedding model does not activate learned workspace retrieval. No source indexing or query is silently transferred to a provider.

Index records carry provider, model, dimension, tokenizer/source-window and index version. Legacy/mismatched spaces are excluded from vector comparisons immediately; local rebuild is scheduled, while lexical/symbol paths remain usable. Incremental patching rebuilds an incompatible index rather than mixing vectors. Local hash-space provenance and cold/incompatible fallback appear in retrieval detail and the shared intelligence result. UI model changes do not change this fixed local space.

The standalone embedText utility now returns vector plus space, transfer status and a finite fallback reason. No production caller currently uses this external utility for workspace ranking. Remote transfer requires an explicit policy (disabled by default); queries-only also requires explicit query classification. Unclassified input is treated as source. Consent is not account-synced. Requests truncate input at 8000 characters, clamp timeout to 50ms–30s (default 5s), cap decoded response bytes at 1MiB and dimension at 16384, reject invalid vectors, cancel response reading on overflow, and preserve caller aborts. Timeout/offline/provider/format failure returns labeled local fallback. No provider error bodies, keys or input text are included in provenance. This does not assert a provider's internal tokenizer or model revision, and returned remote vectors must never be compared to local index vectors.

Validation: 15 focused tests plus typecheck/lint. The fixture rebuilds real temporary indices on provider/model/dimension/tokenizer/version changes, verifies ignored private files stay excluded, and exercises privacy denial, timeout, cancellation, oversized response and invalid vectors. Separate fixed exact-symbol and held-out meaning query groups use the real retrieval ranker. Four exact queries achieved recall@3 1.0; four meaning queries 0.5, with mean precision over returned files 1.0 versus 0.2083. Raw latency samples, fixture digest and limits are in REC-29-calibration.json. This tiny fixture is not a general semantic quality benchmark and was not used to tune ranking. Latencies include a fixture index scan each query; they are not pure warm production lookup latency. No paid/live endpoint, packaged settings UI, GPU or Windows acceptance is claimed. Learned indexing/reranking remains deliberately unimplemented until it has a compatible index lifecycle and a larger held-out relevance corpus.
