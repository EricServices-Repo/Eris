# REC-33 / #78: staged image runtime and download recovery

Repair creates a new private environment at its final stable path and installs dependencies there. Backend/import verification and installed-version provenance complete before an atomic `current.json` pointer activates it. Existing environments and verified model directories are not modified by a failed or cancelled setup. Venv directories are never relocated (their launcher/shebang paths can be absolute). Legacy `venv`/ready layouts remain readable until a successful replacement. Failed staging environments are removed; pip's private wheel cache is retained. A process crash may leave an unreferenced staging directory for manual recovery; no startup scan installs or loads a model.

The versioned dependency constraint set records its requirements digest, Python/platform and resolved package versions. Repair can reuse those exact versions with validated constraints when the backend matches, or the user can request a fresh set. This records reproducibility; it does not claim that every possible ranged dependency resolution or GPU driver has been certified. Python 3.10–3.12 remains the explicit supported interpreter range. Setup checks free disk before installing and does not automatically repeat heavyweight failures. Auth/repository, disk, driver, dependency and cancellation failures have separate recovery guidance and no token-bearing raw errors in saved state.

Settings exposes backend selection (automatic, CPU, CUDA), installed provenance, current setup/download phase, cancellation and retry. CPU fallback is explicit and honored by the worker even when GPU hardware is present. CUDA verification must actually report CUDA; a driver mismatch never silently becomes a different heavy retry. Existing MPS/SDXL limits, selected smaller-model fallback explanation, generation deadlines and offline inference safeguards remain.

Downloads use a persistent `.partial/<model-id>` directory. Hub snapshots remain revision-pinned and verified before publication; cancellation retains resumable partial data. Disk checks include missing data and temporary-file headroom. Corrupt staged files are removed so retry can replace them. Ready metadata is published before the directory becomes selectable; an invalid prior directory is retained as a recoverable backup. The two-directory replacement has a crash window, so unreferenced backups are preserved rather than automatically replayed or erased. Already verified downloads are not overwritten by admission.

Synthetic tests exercise failed/cancelled/CUDA-mismatched environment publication, stable venv paths, legacy compatibility, staged model publication, distinct guidance and existing process/Python image contracts. Actual Windows CPU/CUDA installation, live gated Hub access, and real Mac memory pressure remain separate hardware/network acceptance checks; no heavyweight install or model inference is performed in unit qualification.
