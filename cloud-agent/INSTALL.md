# Eris Cloud Agent — VM install & rebuild

Ops notes for **agents.ericservic.es** (or any Linux VM with NVIDIA + Podman/Docker).

Client URL (no TLS): `http://agents.ericservic.es:6443`

**Source repo is private:** `EricServices-Repo/Eris` — anonymous `git clone` will fail. Authenticate (below) or copy a checkout onto the VM.

---

## One-time host setup

### 1. Clone the private Eris repo

```bash
sudo mkdir -p /opt/eris && sudo chown "$USER:$USER" /opt/eris
```

Pick **one** of these:

**A. GitHub CLI (recommended)**

```bash
# On the VM (browser/device login), or paste a token when prompted
gh auth login -h github.com -p https -s repo
gh repo clone EricServices-Repo/Eris /opt/eris
cd /opt/eris
```

**B. SSH deploy key** (read-only key added under the Eris repo → Settings → Deploy keys)

```bash
# Install the private key as ~/.ssh/eris_deploy (chmod 600)
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/eris_deploy
git clone git@github.com:EricServices-Repo/Eris.git /opt/eris
cd /opt/eris
```

**C. HTTPS + personal access token** (repo read scope; do not commit the token)

```bash
# PAT with Contents: Read on EricServices-Repo/Eris
git clone "https://<TOKEN>@github.com/EricServices-Repo/Eris.git" /opt/eris
cd /opt/eris
# Strip token from remote URL after clone:
git remote set-url origin https://github.com/EricServices-Repo/Eris.git
# Configure credential helper / gh auth so later `git pull` still works
```

**D. No GitHub on the VM** — copy from a machine that already has the repo

```bash
# From your laptop (authenticated):
rsync -a --delete --exclude node_modules --exclude .git/objects/pack.tmp.* \
  ./Eris/ user@agents.ericservic.es:/opt/eris/
# On the VM:
cd /opt/eris
# Prefer keeping .git so rebuild.sh can `git pull` later (rsync including .git,
# or re-clone with A/B/C once credentials exist on the VM).
```

`./cloud-agent/scripts/rebuild.sh` runs `git pull` by default — use `--no-pull` if the VM has no GitHub credentials:

```bash
./cloud-agent/scripts/rebuild.sh --cpu --install --no-pull
```

### 2. GPU toolkit (GPU hosts only — skip on CPU nodes)

```bash
nvidia-smi
sudo nvidia-ctk cdi generate --output=/etc/cdi/nvidia.yaml
nvidia-ctk cdi list
```

Prefer **Podman + Quadlet** on the VM (systemd owns the container).

## Install and run Podman as a systemd service (Quadlet)

This is the supported production path: Podman runs the container; **systemd** starts it on boot and restarts it on failure. You do **not** leave a `podman run` session open in SSH.

### What gets installed

| Piece | Path / name |
|-------|-------------|
| Quadlet unit | `/etc/containers/systemd/eris-cloud-agent.container` |
| systemd service | `eris-cloud-agent.service` (generated by Podman from the Quadlet) |
| Image | `localhost/eris-cloud-agent:latest` |
| Data volume | `eris-cloud-data` → `/var/lib/eris-cloud` (models, jobs) |
| API listen | `0.0.0.0:6443` → `http://agents.ericservic.es:6443` |
| Status page | host `:80` → container `:8080` → `http://agents.ericservic.es/` (no auth) |

### Step 1 — Install Podman (and helpers)

```bash
# RHEL / Fedora / Rocky / Alma
sudo dnf install -y podman git curl jq

# Debian / Ubuntu
# sudo apt update && sudo apt install -y podman git curl jq
```

Confirm Quadlet support (Podman 4.4+):

```bash
podman version
ls /usr/lib/systemd/system-generators/podman-system-generator 2>/dev/null || \
  ls /usr/lib/systemd/system-generators/*podman* 2>/dev/null
```

### Step 2 — Get the private Eris source on the VM

See [Clone the private Eris repo](#1-clone-the-private-eris-repo) above (`gh auth`, deploy key, PAT, or rsync). Then:

```bash
cd /opt/eris
```

### Step 3 — Build the image

**CPU node (no NVIDIA)** — use `sudo` so the image lands in root’s store (required for system Quadlet):

```bash
cd /opt/eris
sudo podman build --target runtime-cpu \
  -t localhost/eris-cloud-agent:latest \
  -t eris-cloud-agent:latest \
  ./cloud-agent
```

**GPU node:**

```bash
cd /opt/eris
# once: nvidia-smi && sudo nvidia-ctk cdi generate --output=/etc/cdi/nvidia.yaml
sudo podman build \
  -t localhost/eris-cloud-agent:latest \
  -t eris-cloud-agent:latest \
  ./cloud-agent
```

### Step 4 — Install the Quadlet unit (systemd service)

Remove any one-shot container that already used the name:

```bash
podman rm -f eris-cloud-agent 2>/dev/null || true
```

**CPU:**

```bash
sudo mkdir -p /etc/containers/systemd
sudo cp /opt/eris/cloud-agent/deploy/eris-cloud-agent-cpu.container \
  /etc/containers/systemd/eris-cloud-agent.container
sudo systemctl daemon-reload
sudo systemctl enable --now eris-cloud-agent.service
```

**GPU:**

```bash
sudo mkdir -p /etc/containers/systemd
sudo cp /opt/eris/cloud-agent/deploy/eris-cloud-agent.container \
  /etc/containers/systemd/eris-cloud-agent.container
sudo systemctl daemon-reload
sudo systemctl enable --now eris-cloud-agent.service
```

**One-liner equivalent** (build + install + start):

```bash
# CPU
./cloud-agent/scripts/rebuild.sh --cpu --install
# GPU
./cloud-agent/scripts/rebuild.sh --install
# Skip git pull if the VM has no GitHub credentials:
./cloud-agent/scripts/rebuild.sh --cpu --install --no-pull
```

### Step 5 — Verify the service is running

```bash
systemctl status eris-cloud-agent.service --no-pager
systemctl is-enabled eris-cloud-agent.service

podman ps --filter name=eris-cloud-agent
curl -sS http://127.0.0.1:6443/v1/health | jq '{ok,ready,gpuMode,localModel,authRequired}'
```

First start downloads Composer Full (~4.7 GB) into the volume. Until then:

- `ok: true` — process is up  
- `ready: false` / `localModel.status: "downloading"` — still fetching the model  
- when ready: `ready: true`, CPU shows `gpuMode: "false"`

### Day-2 operations


### Troubleshooting: `Failed to start eris-cloud-agent.service`

On the VM, get the real error (the one-line journal summary is not enough):

```bash
journalctl -u eris-cloud-agent.service -n 80 --no-pager
systemctl cat eris-cloud-agent.service
sudo podman images | grep eris-cloud
podman images | grep eris-cloud   # user store — systemd cannot see this
```

**Most common cause (Rocky / rootful Quadlet):** the image was built as your login user, but `eris-cloud-agent.service` runs as **root**. Root and user Podman storage are separate.

Fix — build into the root store, then restart:

```bash
cd /opt/eris
sudo podman rm -f eris-cloud-agent 2>/dev/null || true

# CPU:
sudo podman build --target runtime-cpu \
  -t localhost/eris-cloud-agent:latest \
  -t eris-cloud-agent:latest \
  ./cloud-agent

# Confirm root can see it:
sudo podman image exists localhost/eris-cloud-agent:latest && echo OK

sudo cp cloud-agent/deploy/eris-cloud-agent-cpu.container \
  /etc/containers/systemd/eris-cloud-agent.container
sudo systemctl daemon-reload
sudo systemctl restart eris-cloud-agent.service
systemctl status eris-cloud-agent.service --no-pager
curl -sS http://127.0.0.1:6443/v1/health | jq '{ok,ready,gpuMode}'
```

Or re-run the helper (it builds with `sudo podman` when installing the system unit):

```bash
cd /opt/eris
./cloud-agent/scripts/rebuild.sh --cpu --install --no-pull
```

Other checks:

| Symptom | Fix |
|---------|-----|
| `short-name … resolving` / pull from registry | Image missing in root store; use `Pull=never` + `sudo podman build` |
| `port is already allocated` | `sudo ss -lntp \| grep 6443` then stop the other process / `podman rm -f eris-cloud-agent` |
| `executable file not found` / wrong image | Rebuild after `git pull`; confirm `Dockerfile` target `runtime-cpu` |
| SELinux deny | `sudo ausearch -m avc -ts recent \| grep eris` — volume already uses `:Z` |

### Fallback — classic systemd unit (no Quadlet)

If `/etc/containers/systemd` / Quadlet is unavailable:


## Rebuild from CLI (common ops)

After pulling code changes on the VM:

```bash
cd /opt/eris
./cloud-agent/scripts/rebuild.sh
```

What it does:

1. `git pull` (optional; skip with `--no-pull`)
2. `podman build -t eris-cloud-agent:latest ./cloud-agent`
3. Restart `eris-cloud-agent.service` (Quadlet) or recreate the container
4. Print `/v1/health`

### Useful flags

| Flag | Meaning |
|------|---------|
| `--install` | Also copy Quadlet unit + `daemon-reload` + enable |
| `--cpu` | CPU-only image (`runtime-cpu`) + CPU Quadlet (no NVIDIA) |
| `--no-pull` | Do not `git pull` (build local tree only) |
| `--cuda 13.1` | Build with `INSTALL_CUDA_VERSION=13.1` (must be ≤ host driver; ignored with `--cpu`) |
| `--docker` | Use `docker` instead of `podman` |
| `--compose` | `docker compose up -d --build` (uses `docker-compose.cpu.yml` with `--cpu`) |

Examples:

```bash
# Rebuild only (no git pull)
./cloud-agent/scripts/rebuild.sh --no-pull

# CPU-only rebuild
./cloud-agent/scripts/rebuild.sh --cpu --no-pull

# Newer CUDA libs in the image
./cloud-agent/scripts/rebuild.sh --cuda 13.1

# Docker Compose path
./cloud-agent/scripts/rebuild.sh --docker --compose
./cloud-agent/scripts/rebuild.sh --cpu --compose
```

### Manual rebuild (no script)

```bash
cd /opt/eris
git pull
podman build -t eris-cloud-agent:latest ./cloud-agent
sudo systemctl restart eris-cloud-agent.service
curl -sS http://127.0.0.1:6443/v1/health | jq '{ok,ready,localModel}'
```

## Image enhancements (what you get)

1. **Reproducible builds** — `npm ci` from `package-lock.json`
2. **Clean shutdown** — `tini` + `SIGTERM` graceful drain
3. **Resumable model download** — HTTP Range for Composer Full (~4.7 GB)
4. **`ready` in health** — process up (`ok`) vs model can take jobs (`ready`)
5. **Easier ops** — compose file, 600s health start period, `INSTALL_CUDA_VERSION` build arg

## Environment (optional)

Set in the Quadlet file (`/etc/containers/systemd/eris-cloud-agent.container`) or `-e` flags:

| Variable | Default | Notes |
|----------|---------|--------|
| `ERIS_CLOUD_PUBLIC_URL` | `http://agents.ericservic.es:6443` | URL clients use |
| `ERIS_CLOUD_GPU` | `auto` (GPU image) / `false` (CPU image) | `auto` / `cuda` / `vulkan` / `false` / `cpu` |
| `ERIS_CLOUD_MAX_PARALLEL` | `2` | Concurrent jobs |
| `ERIS_CLOUD_DATA` | `/var/lib/eris-cloud` | Models + workspaces |
| `ERIS_CLOUD_ALLOW_ANONYMOUS` | _(unset)_ | `1` = allow unauthenticated jobs (dev only) |
| `ERIS_CLOUD_ERIS_API_BASE` | `https://www.ericservic.es/api/eris/v1` | Bearer token validation (`me.php`) |
| `ERIS_CLOUD_FREE_JOBS_PER_DAY` | `5` | Free-plan daily enqueue cap |
| `ERIS_CLOUD_MAX_CONCURRENT_FREE` | `1` | Free-plan concurrent jobs |
| `ERIS_CLOUD_MAX_CONCURRENT_PRO` | `3` | Pro-plan concurrent jobs |
| `ERIS_CLOUD_LLM_BASE` | _(unset)_ | Optional remote OpenAI-compatible API |
| `ERIS_CLOUD_ADMIN_TOKEN` | _(unset)_ | Shared secret for force-kill-all (`POST /admin/kill-all` on status page / API). Generate a long random string. |
| `ERIS_CLOUD_MAX_THREADS` | `2` (CPU) / unlimited (GPU) | llama.cpp thread cap — keep low on CPU VMs so SSH stays up |
| `ERIS_CLOUD_CONTEXT_SIZE` | `2048` (CPU) / `8192` (GPU) | GGUF context — keep ≤2048 on 8g cgroups (7B+4k OOMs) |
| `ERIS_CLOUD_WARM_ON_START` | `0` (CPU) / `1` (GPU) | Preload GGUF into RAM at boot. **Leave 0 on CPU** or boot OOMs the VM. |
| `ERIS_CLOUD_FLEET_ENROLL_TOKEN` | _(unset)_ | One-time token from EricServic.es Admin → Cloud Agents |
| `ERIS_CLOUD_FLEET_AGENT_ID` / `_SECRET` | _(unset)_ | Skip enroll; use existing fleet identity |
| `ERIS_CLOUD_FLEET_NAME` | _(unset)_ | Display name at enroll |

Fleet / remote config: see [docs/CLOUD_AGENT_FLEET.md](../docs/CLOUD_AGENT_FLEET.md). Website PHP stubs: `cloud-agent/website-stubs/`.

## Status webpage (port 80) + Force kill all

Unauthenticated dashboard (no job goals/tokens). **Force kill all** is on this page.

| URL | Purpose |
|-----|---------|
| `http://agents.ericservic.es/` | Status board + **Force kill all** (nginx :80 → container :8080) |
| `http://127.0.0.1:8080/` | Same board direct (bypasses nginx) |
| `POST /admin/kill-all` | Abort every queued/running job (`X-Eris-Admin-Token`) |

**Why you might see nginx 403 on :80:** the host already runs nginx on port 80. Podman must **not** bind :80. Instead:

1. Container publishes **8080:8080**
2. `rebuild.sh --install` installs `deploy/nginx-eris-cloud-status.conf` → proxies `:80` → `127.0.0.1:8080`

```bash
# On the agent VM (after git pull of cloud-agent >= 0.2.16):
./cloud-agent/scripts/rebuild.sh --cpu --install --no-pull
# Confirm:
curl -sS http://127.0.0.1:6443/v1/health | jq .version   # expect 0.2.16+
curl -sS http://127.0.0.1/ | grep -F 'Force kill all'
podman exec eris-cloud-agent cat /var/lib/eris-cloud/admin.token
```

Admin token: `ERIS_CLOUD_ADMIN_TOKEN`, or auto file `/var/lib/eris-cloud/admin.token`.

Signed-in Eris clients: Settings → Agent → **Stop all my jobs** (own jobs only).

Disable status server: `ERIS_CLOUD_STATUS_ENABLED=0`.

## Firewall

Allow inbound **6443/tcp** (Eris API) and **80/tcp** (status page) from your network, or terminate TLS on a reverse proxy. API remains Bearer-auth; status GET is public; force kill-all needs the admin token (env or auto file).

## Emergency: CPU pegged / SSH dead

Composer Full on CPU can use every core and starve `sshd`. Use the **console / out-of-band** session (provider VNC/serial), not SSH:

```bash
# Stop inference immediately
sudo systemctl stop eris-cloud-agent.service
# or: sudo podman stop eris-cloud-agent

# Confirm load drops, then SSH should work again
uptime

# Upgrade to 0.2.20+ (deferred warm + safe-boot + 2k ctx) and restart
cd /path/to/Eris
git pull
./cloud-agent/scripts/rebuild.sh --cpu --install --no-pull
```

### Why the VM “crashes” when the service starts

Composer Full is a **~4.7 GB** GGUF. On CPU boot the old agent did all of this at once:

1. `warmLocalModel()` → `loadModel` + `createContext` (mmap ~5–8 GB RSS)
2. `WorkerPool` resumed **queued/running** jobs → immediate inference on all cores
3. cgroup `MemoryMax` / host OOM killer → container dies
4. `Restart=always` → repeat until SSH/sshd starve

**0.2.20+ mitigations:** no RAM preload on CPU (`WARM_ON_START=0`), stop queued+running on safe-boot, `CONTEXT_SIZE=2048`, `MAX_THREADS=2`, `--cpus=2`, `Restart=on-failure` + 45s backoff.

CPU Quadlet defaults: `ERIS_CLOUD_MAX_THREADS=2`, `CONTEXT_SIZE=2048`, `WARM_ON_START=0`, `--cpus=2`, `MemoryMax=8G`. Host should have **≥10 GiB** RAM.
